01 — FUNDAMENTE

Ce este GIT?

Git este un sistem distribuit de control al versiunilor, creat de Linus Torvalds în 2005. Urmărește fiecare modificare a codului sursă, permițând colaborarea simultană a mai multor developeri fără conflicte nerezolvate.

Ce este GitHub?

GitHub este o platformă cloud de găzduire a repository-urilor Git, cu funcționalități avansate de colaborare: pull requests, code review, issues, Actions CI/CD și o rețea socială pentru developeri.

02 — FLUXUL DE LUCRU ÎN ECHIPĂ

1

Fork & Clone

Fiecare membru al echipei creează o copie locală a repository-ului. Modificările personale nu afectează codul principal până la aprobare.

git clone https://github.com/org/proiect.git
2

Branch — Izolarea Funcționalităților

Fiecare feature sau bugfix se dezvoltă pe un branch separat. Astfel, ramura principală (main) rămâne stabilă și funcțională în permanență.

3

Pull Request & Code Review

Modificările propuse sunt revizuite de colegi înainte de integrare. Procesul de code review îmbunătățește calitatea codului și transferă cunoștințe în echipă.

4

Merge & Deploy

După aprobare, codul este integrat în ramura principală. GitHub Actions poate declanșa automat testele și deployment-ul în producție.

03 — DE CE CONTEAZĂ

🔒 Siguranța Codului

Nicio modificare nu se pierde. Istoricul complet permite revenirea la orice versiune anterioară în câteva secunde.

⚡ Productivitate Sporită

Zeci de developeri pot lucra simultan pe același proiect, fiecare pe branch-ul propriu, fără să se blocheze reciproc.

👁️ Transparență Totală

Fiecare commit înregistrează cine, ce și de ce a modificat. Responsabilitatea este distribuită și vizibilă.

🔁 CI/CD Automatizat

GitHub Actions automatizează testarea și livrarea. Fiecare push poate declanșa un pipeline complet.

🌍 Colaborare Remote

Echipele distribuite global lucrează eficient. Fusul orar nu mai este o barieră.

📚 Documentare Implicită

Mesajele de commit, issue-urile și pull request-urile formează o documentație vie a proiectului.

06 — BUNE PRACTICI

✍️ Mesaje de commit clare

✗ git commit -m "fix"
✓ git commit -m "fix: rezolvă eroarea 404 la logout"

🌿 Denumire branch-uri

feature/autentificare-oauth
fix/eroare-import-csv
hotfix/vulnerabilitate-xss
docs/actualizare-readme

🔄 Commit-uri atomice

Fiecare commit trebuie să conțină o singură modificare logică. Evitați commit-uri uriașe ce combină zeci de schimbări necorelate.

🛡️ Protejați branch-ul main

Configurați branch protection rules pe GitHub: minim 1 aprobare, teste CI trecute, fără push direct pe main.
